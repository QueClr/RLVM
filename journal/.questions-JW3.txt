JW3 (changelog) - notes and questions for the journal lead, 2026-11-24

1. MONTH TREE AND RELEASE TREE: WHO EDITS THEM
   My task text asks me to maintain trees/log/log-2026-11.tree and trees/log/release-unreleased.tree by
   hand, newest first. journal/.skeleton-ready says the lead owns both files and adds the entries from
   the index file. I followed the ownership note and did NOT edit the two files. The complete bodies are
   at the end of this file, ready to paste; they were built in a scratch copy of the forest together
   with the 68 entries (forester build: no diagnostic). Lines 1-68 of journal/.index-JW3.tsv are in the
   same order as the month list (newest first). The order inside a day cannot be read from the trees:
   \date has no time, so the order of the index (or of the lists below) is the only record of it.
   There is one month tree (log-2026-11) and one release tree (release-unreleased); the last two lines of
   the index say so.

2. DATES
   Every status line of the project carries a UTC time, and by UTC the whole history is 2026-11-24
   (the first commit is 13:44 UTC). The documents and the session trees date the first evening
   2026-11-23 (local time of the commits, UTC-5). I dated four entries 2026-11-23 - the project
   skeleton, the launcher with the placeholder checker (rlvm-cli/README.md: "Measured (2026-11-23 ...)"),
   the arena container and the test corpus (bench/README.md: "2026-11-23") - and everything that has a
   status line with a UTC time 2026-11-24, including the foundation modules (installed 04:53-04:55 UTC,
   which is still 2026-11-23 in local time; session ses-BQZM dates them 2026-11-24 too).
   Question: is the journal's date the local date or the UTC date? If local, only log-2DUU
   (levels, Nat, String) and log-24TH (NDJSON reader) would move to 2026-11-23.

3. \meta{commit}
   The history starts with an import at 13:44 UTC on 2026-11-24, and after it the orchestrator commits
   snapshots of a shared tree, so the source of a change is often in an earlier commit than the one
   whose message records it. Rule used (AGENTS.md: "the commit ... that recorded the change"):
   the commit whose message names the change; where no message names it, the first commit that
   contains the source (only log-I10W, directrules / k2: 468d682); for everything made before the
   history starts, the import commit of the module (6fad0e1 skeleton, 1c3f2e7 bench, 164409d foundation
   modules, 45563d9 reference pipeline, afe1c5b machine). Entries that span several commits name the
   others in the text with \commit{}.

4. AREA TAGS
   One area tag per entry, from the table of AGENTS.md. `soundness` is used for the seven entries whose
   purpose is to remove a verdict that differed from the official checker's (uniform occurrences,
   generated constants / metadata in inductive records, conversion shortcuts S-F1 / S-F2, the
   eager-reduction decline rule, the official level rebuild L-F1, doubled level-parameter records A2-F1,
   typed bindings E1-F1..F6), whatever the module. Free tags are taken only from the list of AGENTS.md
   that are not area tags (loader, store, platform, truffle, levels, nat, benchmark, arena, performance),
   so that no entry carries two area tags.
   The withdrawal of the machine as default engine is in area `machine` (one entry for made + withdrawn).
   The hostile suite and the gates are in `bench-tooling`.

5. SOURCES AND LINKS
   work/ is not tracked, so no entry links to a status log although the numbers come from them
   (work/status/*.log, work/status/integration.md, work/status/machine-integration.md). Each entry links
   to the tracked document nearest to the change (module README, NOTES-*.md, SWITCHES.md, docs/...) and
   to the session tree of its phase. 65 entries also end with "Related:" links to the design, decision,
   insight, example and problem trees that existed at 23:30 UTC (JW2 was done; JW1's design-<slug> and
   dec-XXXX trees existed but JW1 had not signalled completion). If one of those addresses is withdrawn,
   journal-check will name the changelog tree that links to it; the link list is one sentence at the
   end of the entry's last paragraph and can be cut without touching the text.

6. NOT COVERED (left out on purpose, to stay near 70 entries)
   - baseline checkers built and measured (bench/baselines; docs/research/12-baselines.md);
   - rlvm-api publications; exit status 64 for usage errors and engine settings through -X
     (rlvm-cli / rlvm-main, 07:54-08:19 UTC);
   - admission wave 7 (derived terms of a block given back, declines state their cause);
   - machine: far frames as a chain of chunks, OOM-safe growth and counters, the combined constructors
     of the value store, tier hook details, rent-to-own thresholds (one sentence in log-JGIZ), the
     rename of the switches (bodies / directrules / lazycases);
   - bench/track (ladder, regression rule moved from cold CPU time to warm wall clock at 22:13 UTC);
   - prototypes and profiles that changed nothing in the tree (X1, X5, U2, V1 patches, C1, CALL
     instruction, AR1, GC, P8, P9, P10): they belong to the insight trees;
   - the reference kernel's option ref.exact=official: in the tree and in a gate at 22:26 UTC, no
     publication line yet.
