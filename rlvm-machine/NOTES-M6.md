# NOTES-M6 - shared definitions, control, facade (owner: M6)

Deviations from `docs/design/ISA.md` (revision 2) and from `docs/design/review/stepper-convention.md`,
each with its reason. The first section was written by the skeleton agent (2026-11-24); M6 continues it.

## Skeleton (shared definitions and control primitives)

| # | Where | Deviation | Reason |
|---|---|---|---|
| S1 | `Op.MISS` | `MISS = 0x7FFFFFFC`, not `-1` (ISA 13.3) | `-1` is the immediate Nat literal 2^31 - 1 (bit 31 and all value bits set): a `..Fast` method could not tell "miss" from that literal. The new value lies directly below the signals, so `r >= Op.MISS` separates "a result" from "miss or signal". `Layout.MISS` and `Ops.MISS` are aliases |
| S2 | `Layout.TSTAMP_PERM` | `0x3FFFFFFF`, not `0x7FFFFFFF` (ISA 13.3) | `0x7FFFFFFF` is the signal `SUSP`; a memo word must not look like a signal when it travels through an `int` result. Still larger than every check generation |
| S3 | `Machine.hostDepth` | the depth bound D is a per-machine field (default `Op.HOST_DEPTH = 64`), not a compile-time constant (convention H9) | one build runs D = 0 (the worklist machine, H12 item 1), 64 and unbounded in the same JVM; `Fixture.hostDepth(0)` turns every non-leaf call of a test into a suspension. Cost: one field load per judgment that is not answered inline; the convention measured a constant. To be re-measured by M8 on Init (`-Drlvm.machine.hostDepth`) |
| S4 | TICK line | `if ((--m.fuel & Op.POLL_MASK) == Op.POLL_MASK && m.tickSlow()) return m.sig;` instead of `if (--m.fuel < 0) return m.exhaust();` (convention H4, H11) | the convention says the slow part polls every 4096 ticks but its line only enters the slow part on exhaustion. With the mask the slow part runs on exhaustion (`fuel == -1`, all low bits set) and every 4096 ticks, with one counter; a poll that finds nothing lets the judgment continue, which a `return m.exhaust()` cannot. `ticks()` is derived (`tickBase - fuel`), no second counter is written per tick |
| S5 | call event | `if (m.stats) m.call(Op.J);` between TICK and the depth test; `spillN` undoes the tick AND the call event | the convention increments the counter "between 2 and 3" and says it does not depend on D; a spilled judgment is entered twice, so the event must be given back with the tick. `stats` is a per-machine flag (EngineConfig.stats, tests), not a build flavour |
| S6 | frame trace | the trace records `call` events only (the op of each judgment that does work), not `ret` events (ISA 1.3) | under convention H a judgment returns from many places; `ret` events are implied by nesting and would need instrumentation at every return. Equivalence tests compare call sequences, tick counts, value ids and memo contents |
| S7 | TRY frame | `TRY [savedFuel (2), budget (2), savedSsp, savedXp, savedEp, savedRp, savedER]`; no `prevTryp`, the budget instead of `given` | `tryp` is not a register under H (H11); `given = min(budget, savedFuel)` is recomputed; `rp` is the register stack of code activations (H7) |
| S8 | `Frames.k_try` on ABORT | exhaustion (`E_STEPS`) charges the whole segment budget and passes ABORT on iff the budget was capped by the enclosing one (`saved < budget`); a kernel error or `E_LIMIT` charges what was used and gives `U` | ISA 1.4 `exhaust` says "if fuel == 0 and tryp != 0: exhaust()" (also for an uncapped budget that happens to equal the enclosing fuel); the convention's template says `given < budget && fuel == 0`. The convention's rule is implemented (it is the measured one, and it is the same at the top level: a segment capped by the declaration's step limit ends the declaration with `E_STEPS`). ISA 1.4's `cut(g - fuel)` for kernel errors is kept (the template charged the whole budget) |
| S9 | polls at TRY ends | `k_try` polls when charging the segment moved the enclosing fuel across a multiple of 4096 | otherwise a declaration made of many short segments could run for a long time without a poll (ISA 14.4: cancellation within 4096 ticks) |
| S10 | new frame ops | `ARGV 0x14`, `DOM 0x15`, `OFFSET 0x27`, `STRX 0x3B`, `ENSORT 0x46`, `ENPI 0x47`, `ISPROP 0x48`, spare state space `INFER2 / CHECK2 / VTYPE2 / IPROJ2 0x49-0x4C`, `MATCH 0x51`; family `EXT 0x70-0x7F` | under H every operation that calls a sub-judgment is a judgment with frames of its own (the ISA wrote ENSORT, ENPI, ISPROP, OFFSET, STRX as instructions whose inner calls were implicit). EXT is for toy judgments of tests and for experiments (`Machine.ext`) |
| S11 | frame payloads | the payload of `J[k]` is the parameter list of the continuation step `k_Jk` (H2); the payload lists of the table in ISA 1.3 are indicative. Only the frames of the shared control code (`TRY`, `ERF`, `ACT`) have their layout in `Op` | consequence of the convention; frames are private to the judgment that owns them |
| S12 | `Ops` | judgments are called through entry steps `(m, operands.., d)`; the `..Fast` methods remain as pure inline queries; `open`, `tick`, `fail`, `fault` return an `int` (a signal or 0 / the value); no `push<Op>` / `ret` in `Frames` (ISA 13.4) | H3, H8: the fast path is the head of the entry step; failures are signals, not exceptions |
| S13 | `Layout.M_FV0` | FVAR memo word m3 = the `FVAR(type, 0)` record of the variable's type | `CLOSE` then needs no probe to find the scope state; `NEXT` links are learned at `CLOSE` (ISA 2.8 left the linking open) |
| S14 | run header | `rs[r] = len:24 (31..8) | 0:5 | kind:2 (2..1) | far:1 (0)` | ISA 1.6 gives the fields, 13.3 `len = hdr >>> 8`; the positions of kind and far were not fixed |
| S15 | naming | the run-slab pointer is `Machine.rsp` (ISA 1.6 calls it `rp`); `rp` is the register stack pointer (H7) | name clash |
| S16 | `Hash`, `Machine.internRecord`, `addRecordAt`, `addRun`, `putRunAt`, `addPairAt` | the hash functions and the probe sequences of `vtab`, `rtab`, `pair` are frozen shared definitions; `Machine` appends, grows and resets; `Values` / `Runs` / `Pairs` probe | reset in O(used) and growth re-probe every used entry, so they must use the same hash as the interning code (ISA 1.6). A NEU keeps its hash in word c |
| S17 | `Scope` (owner M1), `Values.mkFVar`, accessors of `Values` / `Runs` | delivered implemented | the cut of a speculative segment closes binders; the control tests need working binders |
| S18 | `Machine.Sizes`, per-package `Ext` state | capacities are a constructor argument (`Sizes.tiny()` exercises every growth path); each package keeps private session state in its `Ext` class (`m.x1 .. m.x7`) with `reset`, `beginDecl`, `bytes` hooks | so that packages need no fields in the frozen `Machine` |
| S19 | `Machine.tick(n)`, `sigX` | additions: `TICK(n)` for n > 1; a frame writer whose payload is in scratch | completeness of the primitives |
| S20 | test dependencies | `rlvm-testkit` in addition to ISA 13.1 | `rlvm.testkit.DiffEngine`, the mutant corpus and the official-verdict cache for M8 |
| S21 | `Fixture` | the term language is the S-expression language of `rlvm-ref`'s tests (`Sexp`), not the Lean-like sketch of ISA 13.5; `f.fvar(name, type)` opens a binder of the fixture's context and later terms see the name as a loose bound variable; hand-built inductive blocks are single, non-nested types | a tested parser and prelude exist in that language, `Show.term` prints it, and a machine test row can be compared with the reference test of the same text |
| S22 | `MachineSession.check` | v0: `Machine.reset()` before every declaration and after every outcome other than ACCEPT (`Op.SW_WARM` off) | ISA section 11: "session = one declaration" in v0 |
| S23 | `Decl.check` | returns a `MachineErrors` code (0 = ACCEPT), not an outcome | one integer carries verdict and reason |

Not done by the skeleton (stated, not hidden):

- The `-XX:CompileCommandFile` / `PriorityForceInline` flag sets of H10 are not wired into any launcher
  (M6, once judgments exist to measure).
- `Machine.reset()` does not shrink `S` and `SC`.
- `Debug` only parses names; no audit is implemented.
- Nothing was measured: the control code is tested for behaviour (38 tests), not for CPU time.

## M6 (facade, sessions, debug modes) - continued by work package M6

| # | Where | Deviation / decision | Reason |
|---|---|---|---|
| F1 | `Machine.vbase`, `Machine.rbase` | the records in use are `[vbase, vp)`, the run words `[rbase, rsp)`; ISA 1.6 says "`vp = 2`, `rp = 1`" after a reset | `poison` (ISA 5.5 "ids are shifted at each session reset so that a stale id faults") is implemented as a reset rule: under `DBG_POISON` the next session's records and runs start where the dead session's ended, and the dead words are zeroed (kind 0, empty run). Without the mode the bases never move. Growth, reset and the footprint use the bases |
| F2 | `MachineSession.check`, strict mode | reset before **and after** every declaration in strict mode; v0 (no switch): reset before every declaration and after every outcome other than ACCEPT (S22) | ISA 14.2 says "reset() before and after" for strict; v0 keeps an accepted declaration's values until the next one so that tests (`TierEq`, frame traces) can read them. A second reset of an untouched machine is skipped (`Machine.fresh`) |
| F3 | `MachineSession.check`, `SW_WARM` | the session itself resets when the next declaration is not later in file order (rank <= last rank), in addition to the driver | I-SESSION (ISA 2.5) is a soundness condition of every session memo; the facade does not rely on the caller for it |
| F4 | generation rule (ISA 5.3) | applied by the DECL driver (`Decl.regime`, M5), which knows whether the declaration's roots pass the summary test; the facade only guarantees that every reset starts a session at generation 1. `MachineOps.begin` (no declaration roots) applies the fallback rule itself: `gen++` unless the new universe-parameter list contains the previous one | one place decides; a second `gen++` in the facade would defeat the with-summaries regime in warm sessions (every change of parameters would invalidate all check stamps) |
| F5 | `Session.lastMessage()` | the two values of a mismatch are rendered with `Show.value` (main tree) at the moment of the failure, not read back with `Quote` "only when asked" (ISA 14.1) | `Quote` is in the test tree (ISA 14.6: never on a checking path), and the session is reset before the driver can ask. A judgment that wants its site shown raises `m.fail(code, a, b)`; the rendering runs only on a non-ACCEPT outcome and is clipped |
| F6 | memocheck (ISA 5.5) | "recomputed with the tables bypassed" = the hit's **own entry** is bypassed and the judgment is run again by a nested `m.drive`; memo hits inside the re-computation are trusted (no nesting); a re-computation has a tick budget (default 65536, `-X machine.memocheck.budget`), beyond which the check is *inconclusive* (counted, `machine.memoInconclusive`); `-X machine.memocheck.every=N` samples | bypassing every table for every hit is exponential (each hit would recompute its whole sub-derivation without sharing). Per entry, every memo word is still compared against a derivation that does not read it. The re-computation's own ticks, call events and trace entries are taken back; totals still differ slightly from a run without the mode (Init: 93,555,840 against 93,573,982 ticks), because a re-computation leaves records and memo entries that later judgments find. **Comparison**: the same id; else the same construction up to PEEK (a suspension whose VAL is known by now is its value, a projection of what has become a constructor application is the field); else `CONV` of the two values in the same regime (Init: 72 of 26.7 M checks). Value identity under lazy evaluation depends on what had been forced when a value was built, so id equality alone raised false alarms on 88 units of Init |
| F7 | memocheck hook | the hook sits in the fast path of each memoised judgment and is written by its owner (`Debug.memoCheck` one-liner, or `memoEnter` / `memoExit`); `Debug` knows the `Layout` slots of FORCE, WHNF, CORE, DELTA, VTYPE, DOM, CONV, ISPROP | M6 cannot intercept a memo read: owners read `m.vh` directly. Cost when off: one test of `m.debug` on the hit branch only |
| F8 | scopeaudit | bounded to 96 records per audited value (heads, spines, captured frames, variable types) | ISA 5.5 says "I-FV3 at every GET"; an unbounded walk per variable read is quadratic. A ref outside `[vbase, vp)` or of kind 0 met on the way fails the audit too (stale ids) |
| F9 | maskaudit | the naive mask is exact for indices 0..62; bit 63 of a binder body is resolved with the exact `looseRange` (index 63 exactly -> bit 62, else far), and where that cannot be decided bit 62 is left clear: the audit never over-approximates the naive mask, so it never raises a false alarm; memoised per node (shared nodes for the life of the machine, overlay nodes until the next reset); iterative | a 913,500-deep nest must not recurse; DAG sharing needs the memo |
| F10 | shortcheck | `Debug.shortCheck(m, a, b, answer)`: re-derivation by `Conv.conv` with every staging switch off and the pair's own entry bypassed | "the complete procedure" is rule 3 of ISA 6.3 = no switch; nothing calls it in v0 (no shortcut exists) |
| F11 | statistics | `m.hits[op]` (inline answers from a memo / pair / cache; owners count under `m.stats`), `m.probe(Op.Bk, outcome)`, `m.elabs[role]`, `m.factsDerived / factsNone`; `dumpStats` also writes outcomes by machine error code (`machine.declinedBy.E_x`, `machine.rejectedBy.E_x`) and the first four non-ACCEPT messages (`machine.firstFailures.i`) | ISA 14.5 list, plus what a gate run needs to see why the machine declined |
| F12 | engine settings | `-X machine.switches / machine.debug / machine.hostDepth / machine.memocheck.every / machine.memocheck.budget` through `EngineProvider.optionKeys()` / `factory(Map)`; the system properties `rlvm.machine.*` remain and are overridden | the launcher takes `-X KEY=VALUE` for keys a provider declares (rlvm-api, 2026-11-24) |
| F13 | `MachineSession.driver` | the DECL driver is a field (`Decl::check` by default) | facade tests install toy drivers: every rule of ISA 14 is tested without a judgment of another package |
| F14 | TICK and D = 0 | a judgment that is spilled at a poll point polls twice (once before the spill, once when the driver enters it) | S4 / S5: the spill gives the tick back; the poll cannot be given back. Harmless (a poll has no effect unless it fires) |
| F15 | `MachineOps` | `begin` resets the machine unless `SW_WARM` is on; terms are abstracted over the open locals and values read back with loose indices that are instantiated with the FVAR nodes; `ensureSort` returns the level id of `ENSORT` | ISA 14.6 leaves the bridge between FVAR nodes and machine variables open; the machine's term language has no FVAR node |

| F16 | record limit | at most 2^27 value records per session (`Machine.growRecords`), not 2^28 (ISA section 9) | 8 words per record in one `int[]`: 2^27 records are 2^30 words, the largest array a doubling can reach; the next doubling overflowed (a `NegativeArraySizeException`, which the facade would have declined as INTERNAL_ERROR). `Layout.RECORD_MAX` (2^28) stays the bound of the ref encoding. 2^27 records are 4 GiB, far beyond any budget in use |
| F17 | `Machine.limitDetail` | every refusal that becomes `E_MEM` / `E_STACK` names its limit (records, run words, environment slab, scratch, registers, worklist, `Budget.maxBytes`, the run's watermark); `lastMessage()` adds what was in use | "BUDGET_MEMORY" alone does not say which of eight limits fired; the three `good/perf` tests the machine declines in v0 each hit a different one |
| F18 | `Machine.nats` | an overlay of the machine's own on the base of the binding's `NatStore` (`Machine.ownNats`), emptied by `reset()`, its limbs counted in `engineBytes()`; not the cache store of the context's `NatBinding` (the skeleton's choice) | request of M1 (2026-11-24): `NatBinding` empties its cache on its own schedule (after an operation that leaves more than 32 MiB, at `NatOps.reset()`), which would reissue ids under live NBIG records; e.g. `Infer`'s `ctx.nats.checkLiteralSize` is such an operation. A handle of `m.nats` must be moved with `Nat.transfer` before the binding sees it (`Quote.bigLiteral`, M8). If the binding's store has no frozen base to overlay, the store itself is used as before |
| F19 | memocheck, faults | a broken-invariant fault (`E_HOLE`, `E_INTERNAL`, `E_VIS`, `E_ILLTYPED`) raised inside a re-computation is reported as `E_AUDIT` with the judgment and its key; cancellation, memory limits and a nested failed audit are passed on unchanged | the first debug run found a hook that re-computed with a wrong argument; "E_HOLE at beta_reduction2" did not say that a re-computation raised it |

| F20 | the Java heap | `Machine.heapAllows(bytes)`: a session array of 32 MiB or more grows only if the new array fits into the heap with 256 MiB to spare (twice the array when the engine has several workers), measured after a `System.gc()` if the first reading says no; otherwise `E_MEM` (`limitDetail` = "the Java heap: ..."). Void growth paths (run and pair tables, pair log) throw `Machine.HeapLimit`, which the facade turns into `E_MEM` | ISA section 9 knows the array limits and the byte budget, both in bytes *in use*; a doubling array needs its new capacity beside the old one, which neither the budget nor the driver's memory account sees. On Std one declaration doubled the record array to 4 GiB in a 13 GiB heap: `OutOfMemoryError`, and under `ExitOnOutOfMemoryError` the whole run ended with status 3 instead of declining one unit |
| F21 | intern table growth | `vtab` grows when the LIVE records (`vp - vbase`) pass half of its slots, not `vp` | under `poison` `vp` keeps growing across sessions |

| F22 | `Op.HOST_DEPTH` | 128, not 64 (convention H9, ISA 13.3) | M8's frame counts on Init, real checking (machine-frames-init*.txt): D = 64 writes 0.234% of the call events as frames, above the 0.1% bound of H12 item 2; D = 128 0.041%; D = 256 0.017%; ticks, call events and outcomes identical. | F23 | H10 inlining directives | `h10/hotspot-inline.cmd` measured on Init (same setting and rounds as F22): 15.30 / 16.94 / 17.27 s with the directives (mean 16.50) against 14.98 / 16.98 / 15.89 s without (mean 15.95) - no gain on C2 (the difference is inside the round-to-round spread of about 2 s), as the convention found on the spike. Not wired into a launcher. Not measured on the Graal JIT or the native image |
