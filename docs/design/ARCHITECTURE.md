# RLVM architecture - everything around the machine

Scope: the persistent store, the loader, declaration admission and its policies, the reference kernel,
the scheduler, the runtime platform, the verdict protocol, testing, milestones and staffing. The machine
itself (instruction set, values, code objects, memo semantics, tiers, Truffle mapping) is `ISA.md`;
section 11 is the boundary between the two documents.

References: `R01`..`R11` = `docs/research/NN-*.md` (R10 was not available when this was written; the
platform numbers are taken from the raw files in `spikes/platform/results/`). `[meas]` = measured on this
host (file named), `[src]` = read in a research document, `[est]` = estimate with the arithmetic shown.
Skeleton code for every module defined here exists and compiles: `rlvm-store`, `rlvm-api`, `rlvm-load`,
`rlvm-ref`, `rlvm-inductive`, `rlvm-admit`, `rlvm-driver`, `rlvm-main`, `rlvm-testkit`. Java signatures
quoted below are the ones in those skeletons. The launcher, the exit-status protocol and the build and
measurement scripts already exist (`rlvm-cli/README.md`, `scripts/`, `bench/rlvm/`); this document builds
on them and says where they must change.

Mathlib reference numbers used throughout (exact, `work/exports/stats/mathlib.stats.json`): 6,326,141,213
bytes; 112,081,718 lines; 107,037,712 expression records (app 91,561,354; lam 8,241,106; forallE
5,475,525; const 1,442,301; letE 255,403; proj 34,595; strVal 19,699; natVal 5,660; sort 1,709; bvar 360);
4,273,914 names; 48,246 levels; 721,845 declaration records = 739,167 constants (thm 524,582; def 187,271;
opaque 2,855; axiom 4; quot 4; 7,129 inductive blocks with 7,162 types, 10,006 constructors, 7,283
recursors, 14 mutual blocks, 57 nested types). Longest line 2,713,224 bytes (a string literal); largest
declaration 92,478 records; 1,820 Nat literals of 2^64 or more, the longest 1,085 digits.

## 0. Decisions in one page

1. **One shared store of flat `int[]` regions, frozen progressively.** A term is an `int`; a node is 8
   ints (32 bytes) carrying everything consumers need (kind, three payload words, loose-variable range,
   64-bit free-variable mask, `depMax`, `lpSet`). Flat arrays, not chunks (+25 % per access, R11 B.3), not
   `MemorySegment` (1.9x).
2. **Two summaries per node make the per-declaration structural checks O(1)** and make cached facts
   order-independent: `depMax` (largest rank of a constant below the node) and `lpSet` (set of universe
   parameter names below it). "Every constant is declared earlier", "every universe parameter is
   declared" and "closed" are three integer tests at the declaration's roots.
3. **One pass over the file.** Expression records are buffered per declaration; at the declaration line
   they are split into shared terms and one packed proof block (theorem and opaque values). A block
   record that a later declaration references is promoted into the shared region on demand. No prescan,
   no whole-file column set, 4 bytes of transient state per record.
4. **Proof blocks stay packed** (about 5.5 bytes per record, LEB128) until a worker checks or unfolds the
   theorem; they are decoded into that worker's overlay in one forward pass.
5. **Loading, environment construction and checking overlap.** The loader publishes finished units; an
   environment thread admits inductive blocks and the quotient package ahead of the workers and publishes
   the derived facts; workers check everything else. Two publication frontiers and one failure mark,
   no locks on any hot path.
6. **Optimistic environment, pessimistic verdict.** A worker reads the statements of earlier declarations
   before they are checked; the file is accepted only if every unit is. Verdict: REJECT iff some rejection
   was confirmed by the reference kernel, else DECLINE iff anything was declined, else ACCEPT. The
   launcher's status starts as 3 (internal error) and receives a verdict in exactly one place.
7. **Nothing derived is read from the export.** Inductive facts and recursors are regenerated by
   `rlvm-inductive` and compared structurally with the exported records; only derived facts enter the
   declaration table's side tables. Where an exported term is identical to the derived one, the exported
   term id is used, so nothing has to be copied.
8. **The reference kernel is a complete engine**, not a helper: it runs the environment pass, re-checks
   every rejection, is the oracle of the differential tests, and can check a whole library alone. The
   pipeline is therefore complete and testable before the machine exists (milestones M1-M3).
9. **Engines sit behind one facade** (`rlvm.api.Engine` / `Session`): "check constant `cid`, return
   ACCEPT / REJECT / DECLINE", `KernelOps` for admission code, statistics dump. Engine modules register
   through `ServiceLoader` (`rlvm.api.EngineProvider`), as checkers do with the launcher.
10. **Sessions**: per worker; overlay terms plus engine arenas; reset at 32 MiB, on any non-ACCEPT
    outcome, when the next unit is not later than the last one, and when the level snapshot changes.
11. **Parallel by default**: 6 workers + loader + environment thread on the 8-vCPU runner; verdict
    independent of the worker count by construction (step budgets, cold re-check, no time-based decisions).
12. **Runtime**: one native-image binary with the Truffle runtime linked in, Serial GC, working set in
    primitive arrays; the same jars remain launchable on the JVM, and the shipped mode is decided by a
    measurement gate on mathlib (section 7.1) because the JIT produces better code than the CE AOT compiler.
13. **Policies**: accept every well-typed axiom; drop unsafe/partial records; shape guards on the prelude
    constants behind the literal extensions, declining only if an invalid one is actually used; malformed
    input is rejected exactly where the official reader rejects, declined where RLVM is merely narrower.

Where the owner's vision overrides the research documents, and what it costs:

| Vision | Research position | Decision here | Cost |
|---|---|---|---|
| parallelism and wall clock are first-class | R11 C.9: one worker by default, every worker costs instructions | 6 workers by default, pipelined loader | +0.8 % (4 workers) to +1.6 % (8) instructions in a design without collector work [src gruszka, R05 2.10]; gate: the default is the largest N <= 6 whose measured mathlib overhead against N = 1 is <= 2 % |
| the machine carries essentially all checking work | R03 decision 9: admission on a substitution reducer | def/thm/axiom/opaque go to the machine; only inductive blocks and quot (1 % of units) and re-checks use the reference kernel | environment pass about 10 G instructions on mathlib [est, 4.6], off the workers' path |
| base tier is plain Java compiled ahead of time (decision E) | raw spike numbers: the HotSpot JIT needs 0.69x the instructions of the CE native image on the object NbE benchmark and 0.66x on the plain interpreter, after a warm-up that costs 9-90 G (7.1) | native image first, platform gate at M5 | up to 1.4x on steady-state code if the gate is skipped; the gate costs one measurement campaign |

## 1. Module map

### 1.1 Dependency graph

```
layer 0  (exist, no RLVM dependency)   rlvm-export    rlvm-level    rlvm-nat    rlvm-cli (launcher + Checker SPI)
layer 1  rlvm-store      ->  JDK only
layer 2  rlvm-api        ->  store                       (later: level, nat, for the bindings)
         rlvm-load       ->  store                       (later: export, level, nat)
layer 3  rlvm-ref        ->  store, api
         rlvm-inductive  ->  store, api
         rlvm-machine    ->  store, api                  (ISA.md; name reserved)
         rlvm-truffle    ->  machine, Truffle artifacts  (ISA.md; name reserved)
layer 4  rlvm-admit      ->  store, api, inductive
layer 5  rlvm-driver     ->  store, api, load, admit
layer 6  rlvm-main       ->  driver, load, admit, api, store   (later: cli, export, level, nat)
         rlvm-testkit    ->  store, api, load, driver
run time (ServiceLoader): rlvm-cli finds rlvm-main as a rlvm.cli.Checker;
                          rlvm-main finds rlvm-ref and rlvm-machine as rlvm.api.EngineProvider
```

Rules: a module depends only on lower layers; there are no cycles; `rlvm-driver`, `rlvm-admit` and `rlvm-main`
never see an engine class (engines arrive as `EngineFactory` from an `EngineProvider`); nothing depends
on `rlvm-main` or `rlvm-testkit`; besides `rlvm-cli` (its Truffle probe) only `rlvm-truffle` depends on
Truffle artifacts. The distribution puts every module jar on one class path (`scripts/build.sh`). Until the wave-2a modules are frozen, the new modules use
adapter interfaces of their own (`rlvm.api.LevelOps`, `rlvm.api.NatOps`, `rlvm.store.IntLists`,
`rlvm.load.RecordSink`, `rlvm.load.LevelInterner`, `rlvm.load.NatDecoder`); the bindings (about 300 lines)
go into `rlvm-api` (`rlvm.api.bind`) and `rlvm-load` when those poms gain the dependencies.

## 2. Persistent store

### 2.1 Term node: 8 ints, 32 bytes

```
word 0  header   bits 0..3 kind | bits 4..15 flags | bits 16..31 looseRange (u16, saturating at 0xFFFF)
word 1  a   \
word 2  b    }   payload, by kind
word 3  c   /
word 4  fvMask low      bit i (i < 63): de Bruijn index i occurs free below this node
word 5  fvMask high     bit 63: some index >= 63 occurs free
word 6  depMax          largest rank of a constant in the sub-DAG; 0 = none; 0x7FFFFFFF = unresolved
word 7  lpSet           list id of the sorted set of universe-parameter names in the sub-DAG; 0 = none

kind        a                              b                      c
1 BVAR      index
2 SORT      level id
3 CONST     cid, or ~nameId if unbound     level-list id          name id
4 APP       function                       argument               head of the spine
5 LAM       binder domain                  body                   (reserved for the elaborator)
6 PI        binder domain                  body                   (reserved for the elaborator)
7 LET       type                           value                  body
8 PROJ      structure expression           field index            cid of the structure type, or ~nameId
9 NATLIT    low 32 bits                    high 32 bits           -        (flag NAT_BIG: a = LitPool index)
10 STRLIT   LitPool string index           number of code points
11 FVAR     serial                         type term              (overlay only: reference kernel, admission)

flags (header bits)  4 HAS_LPARAM   5 HAS_CONST   6 HAS_LIT   7 HAS_LET   8 HAS_PROJ   9 HAS_FVAR
                     10 UNRESOLVED (an unbound CONST/PROJ, or a CONST with the wrong number of levels, below)
                     11 LOOSE_SAT   12 NAT_BIG    13..15 reserved for the machine's elaborator
```

Not stored: binder names, binder info, `nondep`, `mdata` (the loader returns the wrapped expression).
R03 section 2: this differs from the official checker only on hand-written files, in the accepting
direction, on semantically irrelevant data.

Derivation, done once when the node is written (loader, block decoder, overlay constructors; identical
code, `TermStore.appendExport`):

```
looseRange: bvar i -> i+1 | app -> max(f, a) | lam, pi -> max(dom, body-1) | let -> max(ty, val, body-1)
            | proj -> struct | else 0                                  (saturate; exact value by walking)
fvMask:     bvar i -> 1 << min(i, 63) | app -> f | a | lam, pi -> dom | under(body)
            | let -> ty | val | under(body) | proj -> struct | else 0
            under(m, range) = (m >>> 1) | (range > 64 ? 1 << 63 : 0)                      (R09 1.2)
depMax:     const -> rank(cid), or UNRESOLVED | proj -> max(struct, rank(structure cid))
            | natlit -> specials.natLiteralRank() | strlit -> specials.stringLiteralRank()
            | else max over children
lpSet:      sort l -> params(l) | const -> union of params of its levels | else union over children
            (union memoised on the id pair; 0 with 0, x with x and x with 0 are free)
flags:      or of the children's flags, plus the node's own
```

A literal's `depMax` is the rank of its last prerequisite constant (`Nat`, `Nat.zero`, `Nat.succ`; for
strings also `String`, `String.ofList`, `Char`, `Char.ofNat`, `List.nil`, `List.cons`), or UNRESOLVED when
they are not all declared yet: a literal "mentions" them, which is what makes facts about literals
monotone (4.1).

Why AoS and 32 bytes: one cache-line touch per node for every consumer (the machine reads kind, children
and mask together); R11 B.3 measured equal instructions for parallel columns and one interleaved `int[]`
(29.2 against 30.5 per visit) and better CPU time for columns in a DFS that reads two fields. Work package
WP-A1 repeats that measurement with the real access pattern (decode a block, walk it reading five fields)
in the native image before the layout is frozen; the accessor API (`Terms`) hides the choice.

### 2.2 Regions, ids, sizing

```
term id (int)   bit 31 = 0 always: negative ints belong to the machine (value tags)
  1 .. 0x0FFFFFFF               export region     shared; writer = loader thread
  0x20000000 | i                generated region  shared; writer = environment thread; empty for canonical files
  0x40000000 | i                overlay           one per worker
word 0 of node id = (id & 0x0FFFFFFF) << 3 in its region's int[]
```

- A region is one flat `int[]`; at most 2^28 - 1 nodes (array length 2^31 - 8). More shared nodes than
  that is `UnsupportedExportException` (decline).
- Export region capacity: `inputBytes / 144` nodes [est: mathlib has 56.35 bytes per expression record
  and 36 % of the records end up shared (38 M of 105 M, R05 0.2), so 1 node per 156 input bytes; 144 is
  8 % above that]. Mathlib: 43.9 M nodes = 1.41 GB allocated, about 40 M used. If it fills, the writer
  allocates 1.25x, copies, and publishes the new array with the next frontier; readers call
  `Terms.refresh()` once per unit. Old arrays stay valid for everything published before.
- Overlay: one `int[]` per worker of `sessionBytes / 4` ints (32 MiB = 8,388,608 ints = 1,048,576
  nodes); doubles by reallocation if one declaration needs more (the largest mathlib proof is 92,478
  records = 3 MB) and returns to the base size at the next reset.
- Reading (`Terms`): `id >= OVERLAY_BIT ? overlayArray : (id < GEN_BASE ? exportArray : generatedArray)`,
  then one bounds-checked load; the arrays are fields of the worker's `Terms`.

### 2.3 Names

```
per name id, 5 ints (20 bytes); id 0 = anonymous
w0 prefix id | w1 bit 0 numeric, bit 1 root component is "_nested", bit 2 root is "_private", bits 8..31 byte length
w2 string: offset into the UTF-8 pool; numeric: low 32 bits | w3 string: 32-bit hash; numeric: high 32 bits
w4 constOf: cid declared under this name; 0 none; -1 dropped (unsafe/partial)
intern index: open addressing int[] of name ids, 2^23 slots for mathlib (load 0.51), key (prefix id, component)
```

Names are interned structurally at load (a name id means a name, whatever ids the file used: R01 2.5), so
"same name" is an integer comparison everywhere and the level store's requirement on parameter names
holds. Cost: one probe per name record, about 120 instructions x 4.27 M = 0.5 G on mathlib [est, probe
cost from R11 B.5]. Components above 2^64 are stored as digit strings with the numeric bit
(`internNumBig`). `constOf` is the flat-namespace guard: `NameTable.claim` is a compare-and-set, so the
second declaration of a name fails whichever thread makes it and whichever kind it has.

### 2.4 Levels, lists, literals

- Levels are ids of `rlvm-level`'s store: shared base built by the loader with the plain constructors
  (export records are kept as written, because recursor types are compared syntactically), one overlay
  per worker. The store holds only level ids (`SORT.a`) and list ids (`CONST.b`, `lparams`).
- One list store for the run (`rlvm.level.IntListStore` behind `rlvm.store.IntLists`): level lists,
  parameter-name lists, constructor lists, recursor rule tables (triples), `lpSet` sets (sorted).
- `LitPool`: naturals of 2^64 and above as little-endian 64-bit limbs; strings as UTF-8 plus a lazily
  built code-point index (4 bytes per scalar, only for strings that are actually indexed). Smaller
  naturals live in the node. A worker has its own pool for computed numbers (negative indices).

### 2.5 Declaration table

One row per constant (`cid`, dense from 1 in file order) and one row per unit (declaration record; an
inductive block is one unit holding its types, constructors and recursors).

```
constant row, 8 ints
w0 bits 0..3 kind (AXIOM DEFN THM OPAQUE INDUCT CTOR REC QUOT_TYPE QUOT_MK QUOT_LIFT QUOT_IND)
   bits 4..15 flags (UNFOLDS, BLOCK_VALUE, GENERATED, BLOCK_MEMBER) | bits 16..31 number of universe parameters
w1 unit | w2 rank | w3 name id | w4 type (shared term)
w5 value: DEFN shared term; THM/OPAQUE shared term or -(block+1); CTOR cid of its type; else 0
w6 DEFN: reducibility hint 0 = opaque, 1+h = regular h, 0x7FFFFFFF = abbrev (larger unfolds first); THM 0;
   INDUCT/CTOR/REC: row in the side table | w7 universe-parameter names (list id)
unit row, 4 ints: first cid | number of constants | record kind | reserved      + status (atomic int column)
inductive side row, 8 ints: numParams | numIndices | numCtors | ctors list | all list
                            | flags REC, REFLEXIVE, STRUCT_LIKE, UNIT_LIKE, ONE_CTOR | numNested | cid of I.rec
constructor side row, 4 ints: inductive cid | cidx | numParams | numFields
recursor side row, 8 ints: numParams | numIndices | numMotives | numMinors | flags K | rules list
                           | index of the major premise | cid of the major's inductive type
rules list: (constructor cid, nfields, rhs term) triples
unit status: LOADED -> ENV_READY -> RUNNING -> ACCEPTED | REJECTED | DECLINED ; SKIPPED for dropped records
```

Every fact the kernel reads is here and nowhere else: delta (`UNFOLDS`, value, hint, number of level
parameters), iota (major index, K, rules by constructor cid, `nfields`), structure eta and unit-like
(`STRUCT_LIKE`, `UNIT_LIKE`, constructor `numParams`/`numFields`), projection typing (`ONE_CTOR`,
`numParams`, `numIndices`), K (`K`, major's inductive, its first constructor), quotients (kind),
literal extensions (`Specials`). Side-table values are derived by admission (4.6); what the export
claimed is held only in a per-block claims blob that is dropped after the comparison.

### 2.6 Proof blocks

A block holds the expression records of one declaration segment that the declaration's type does not
reach: in practice the proof of a theorem or the value of an opaque (never unfolded, R03 4.2).

```
storage   byte[][] of 1 MiB; per block 6 ints: chunk, offset, bytes, nodes, root (record index of the
          owner's value, -1 if none), firstRecord (block records are numbered globally by prefix sum)
record    tag:u8 (bits 0..3 kind, bits 4..7 small field), then LEB128 varints
ref       r even -> record (k - r/2) of this block, r/2 >= 1          r odd -> shared term id r >>> 1
APP ref ref | LAM, PI ref ref | LET ref ref ref | PROJ cid(zigzag) index ref | BVAR small or varint
SORT level | CONST cid(zigzag) levelList name | NATLIT value or pool index | STRLIT pool index
```

Size [est]: an `app` record is 1 + 1..2 (local distance; 37 % of references point to the previous record,
R01 2.12) + 1..4 (a shared id is up to 4 bytes) = about 5.5 bytes; 67 M block records = 0.37 GB (the
NDJSON for them is 3.8 GB). A per-block table of distinct shared ids ("frontier", as in Susz) would save
about 1 byte per record and is left as an optimisation.

Decoding (`Overlay.blockRoot(block)`): one forward loop appending 8 ints per record to the worker's
overlay with the derivation of 2.1; no recursion, no hash-consing (block records are already distinct);
budget 60 instructions per record = 4.0 G for all of mathlib. A block decoded for unfolding a theorem is
kept until the session resets.

### 2.7 Special constants and shared facts

`Specials` binds the 34 names the kernel knows (`Nat` .. `eagerReduce`, section 4.8) to cids and records
a guard state per name (ABSENT, VALID, INVALID); `which(cid)` is one array load. `SharedFacts` is one byte
per export-region node written racily and idempotently: bit 0 = "this closed shared term passed check
mode" (the machine's `PCHK`, ISA.md 1.5). No stamp is needed: by 2.1 the fact is usable for a unit of rank
`r` with parameters `L` iff `depMax(t) < r` and `lpSet(t)` is a subset of `L`, and both hold for every term
reachable from roots that passed the structural checks.

### 2.8 Frozen base, overlays, who writes what

| Structure | Writer | Readers | Published by |
|---|---|---|---|
| export region, names, literals, lists, levels, proof blocks, constant and unit rows | loader thread | everyone | `Store.loadedUnits` (volatile, monotone) |
| inductive / constructor / recursor side rows, `Specials`, generated region, generated constants | environment thread | everyone | `Store.envUnits` (volatile, monotone, <= loadedUnits) |
| unit status, `VerdictBoard` | any worker (CAS / atomic min) | driver | - |
| `SharedFacts`, the machine's per-constant static facts and code objects | any worker (racy idempotent / publish-once, R11 C.3) | workers | - |
| overlay terms, worker lists, levels, literals, engine session | owning worker | owning worker | - |

Contract: everything reachable from a unit below a frontier is immutable. A worker may check unit `u` only
if `u < envUnits`; it then needs nothing above `u`. No structure is ever locked on a hot path.

## 3. Loader pipeline

### 3.1 Stages and threads

```
$IN --read() into reused buffers--> rlvm-export reader --ExportSink events--> rlvm.load.Loader --> Store
     (optional: K scan helper threads)        (one "loader thread" calls the sink, in file order)
```

The reader parses bytes into record events (canonical byte templates with SWAR integers, generic JSON
for every line that does not match; R01 2.3, 2.13) and translates the file's ids into the ids the sink
returned. The loader interns, buffers, splits, writes and publishes. Nothing in this pipeline recurses
on expression depth: every per-node fact is derived from children that already exist (R01 2.13:
`perf/app-lam` nests 19,999 deep).

Ids the loader returns to the reader: store name ids (structurally interned), level ids, and for
expressions the **record ordinal** 1, 2, 3, ... in arrival order. Ordinals are consecutive, so the reader
needs no translation table on a canonical file. Where a record finally lives is the loader's business:

```
loc[ordinal]   > 0  shared term id        < 0  -(global block record + 1)        0  still in the segment buffer
seg            the current segment: 4 ints per record (kind and small field, a, b, c; children as ordinals)
promo          open-addressing int -> int: global block record -> shared id, for promoted records
```

### 3.2 What happens per record

| Event | Work | Budget (instr) |
|---|---|--:|
| `nameStr` / `nameNum` | probe the name index, append 5 ints (+ bytes) | 150 |
| `level*` | `LevelInterner` (plain constructors) | 150 |
| `exprApp` (85.5 % of expression records) | check the two child ordinals exist, append 4 ints to `seg` | 30 |
| `exprLam`, `exprForall`, `exprLet`, `exprProj`, `exprBVar`, `exprSort` | same | 30-40 |
| `exprConst` | intern the level list (most are 0-2 long and repeat), append | 120 |
| `exprNatLit` | up to 19 digits inline, else `NatDecoder` to limbs in the `LitPool` | 60 + digits |
| `exprStrLit` | copy bytes to the `LitPool`, count scalars | 40 + bytes |
| `exprMData` | return the wrapped ordinal | 5 |
| declaration | section 3.3 | 70 per segment record + 400 |

### 3.3 Ownership: one pass, per-declaration segments, promotion on demand

About 80 % of the expression records are reachable only from one theorem's proof (R01 2.12; mathlib:
67 M of 105 M, R05 0.2), but 5 % of those are referenced again by later declarations, so ownership cannot
be decided when a record arrives. Options:

| Option | Extra work | Transient memory | Checking can overlap loading |
|---|---|---|---|
| (a) prescan: a first pass counts references or last uses, a second pass loads (rpylean, R07 1.3) | a second scan of 6.33 GB, at least 2.5 instr/byte = 16 G | 4 B per record = 0.43 GB | no |
| (b) parse everything into columns, one backward ownership sweep, then pack (Susz, R05 1.3) | a second and third sweep over 107 M cold records, about 3 G | 13 B per record = 1.39 GB (Susz: 1.6-1.8 GB peak) | no |
| (c) **chosen**: decide at each declaration line from that declaration's own roots; promote later references | promotion: about 8 % of block records [est] x 120 instr = 0.65 G; the promoted records also stay in their block (30 MB) | 4 B per record = 0.43 GB (`loc`) | yes |

```
onDeclaration(kind, names, lparams, typeOrd, valueOrd, ...):            // exprs since the previous declaration = seg
  claim the declared name(s)                                            // before the sweep: self-references bind
  if kind in {THM, OPAQUE} and proofBlocks:
      mark := records of seg reachable from typeOrd                     // explicit stack, stays inside seg
      for r in seg, in order:
          if mark[r]:  loc[r] := builder.<kind>(shared(children))       // shared node, facts derived (2.1)
          else:        writer.<kind>(ref(children)); loc[r] := -(firstRecord + local + 1)
      block := writer.finish(local index of valueOrd, or -1)
      value := loc[valueOrd] > 0 ? loc[valueOrd] : -(block + 1)
  else:                                                                 // def, axiom, quot, inductive
      for r in seg: loc[r] := builder.<kind>(shared(children))
  write the row(s); clear seg; publish if due (3.5)

shared(c):   l := loc[c];  if l > 0 return l;  s := promote(-l - 1);  loc[c] := s;  return s
ref(c):      c in seg and not marked -> local back distance;  else shared(c)
promote(g):  if promo has g return it
             over the prefix of g's block: mark backwards from g, then copy the marked records forwards
             into the export region (marked child -> its new id, shared ref -> as is), promo.put(each)
```

Consequences:
- A theorem's type, every definition and every inductive record is shared at once; a theorem's or
  opaque's value is a block unless its root is reachable from the type or already existed.
- Records that no root of their segment reaches (lean4export writes the block of `Nat` in the middle of
  the first declaration that needs a Nat literal, R01 2.5) go to the block and are promoted when the
  later record references them. A hostile file can force many promotions, but each record is promoted
  at most once: the total stays linear.
- Promotion appends to the export region out of file order. That is harmless: nothing relies on shared
  ids being ordered, and children are always written before parents.
- `CONST` and `PROJ` are bound to constant ids when the node is written (after the unit's names were
  claimed), so the members of an inductive block see each other, and a theorem that mentions itself gets
  `depMax = own rank`, which the structural check turns into "unknown constant" (4.3).

### 3.4 Non-canonical and hostile input

| Input property | Handling | Verdict if it matters |
|---|---|---|
| keys in another order, whitespace, `\uXXXX` escapes, CRLF, no final newline | reader's generic JSON path for that line (271 lines of 8 hand-made tests, R01 2.10) | none |
| sparse or out-of-order ids (`other/sparse-name-index`, `level-index-out-of-order`) | reader's `IdSpace` tables; the loader never sees file ids | none |
| id used before definition, id bound twice, blank line, non-digit `natVal`, unknown record shape | `MalformedExportException` | reject (official: uncaught exception, exit 1) |
| declaration name declared twice, in any kinds, including the members of a block | `NameTable.claim` fails | reject (tutorial 132-139) |
| garbage or missing first line | line 1 is never interpreted (official skips it unread); a missing meta line swallows the first record exactly as the official reader does | as official |
| meta present with a format major version other than 3 | `UnsupportedExportException` | decline |
| two name ids for one name, two expression ids for one term | names: interned; terms: both kept (id equality is sufficient for equality, never necessary) | none |
| ids or indices beyond 2^63, more than 2^28 - 1 shared nodes, de Bruijn index above 2^31, numeric hint above 2^32 | reader reduces / declines as documented in `ExportSink`; loader declines | decline |
| lines of any length (2.7 MB in mathlib), numerals of any length, strings with every escape and U+0000 | growing carry buffer; sub-quadratic decimal conversion; code points, never chars (R01 2.5) | none |
| loose bound variable, wrong universe arity, unknown or later constant in a root | flagged in the node summaries, decided in 4.3 | reject or decline per 4.2 |
| `unsafe` / `partial` records, `isUnsafe` inductive | dropped, name remembered (4.5) | users reject |
| `mdata` | wrapped expression | none |
| a segment or a store that exceeds the memory limit | `UnsupportedExportException` | decline |

### 3.5 Publication, pipelining, parallel scanning

- Batch mode (`LoadOptions.batch`): one publication at end of file; the level store is frozen once. The
  default until `rlvm-level` offers a snapshot (1.4), and the reference configuration for debugging.
- Pipelined mode (`LoadOptions.pipelined`, the arena default): after every 4,096 units or 32 MiB of input
  the loader calls `LevelInterner.publish()` and then `Store.publishLoaded(n)`: about 200 hand-offs on
  mathlib [6.33 GB / 32 MiB]. Workers and the environment thread park and are unparked at hand-offs;
  nobody polls (R11 0.10: parked time is kernel time, spinning is billed).
- A worker's level and list overlays are built on the snapshot that was current when its session
  started. A unit beyond that snapshot makes the worker reset its session and take the newest snapshot
  first (at most 200 forced resets per worker on mathlib; sessions reset far more often anyway, 6.4).
- Parallel scanning (`rlvm.export.ParallelScan`): K helper threads tokenise file ranges, the loader thread
  replays them in order. It buys wall clock only, at about +0.5 instr/byte for the hand-over [est] (+3 G
  on mathlib). Default K = 0: with 6 workers the loader is not the bottleneck (load 50 G on one thread
  against 325 G on six, 3.6 and 6.8). `-X scan-threads=K` exists for the day that reverses.
- Wall-clock model for mathlib on 8 vCPUs at 3 G instr/s per core [nano-lean retires 3.25, R01 1.2]:
  batch = 17 s load + 18 s check = 35 s; pipelined = max(17, 18) + tail = about 20 s; `-j 1` pipelined =
  about 110 s. (nano-lean 36.8 s, gruszka 32.5 s with 4 threads.)

### 3.6 Instruction budget of loading

Ceiling **8 instructions per input byte** end to end (50.6 G on mathlib, 13 % of the leader's total),
target 6 (38 G). Reference points: Susz packs the same file at 5.4 instr/byte in Rust (R05 1.3); nano-lean
spends 62 instr/byte on everything (R01 0.2).

| Per `app` line (50-54 bytes with 9-digit ids) | instr |
|---|--:|
| reader: template match, three SWAR integers, id check | 180 |
| sink call, child checks, segment append | 30 |
| declaration sweep: classify, write 8 ints with derived facts or 2 varints, `loc` store | 70 |
| total | 280 = 5.4 per byte |

`lam`/`forallE` lines (86-89 bytes) cost about 420 (4.8 per byte), name lines 300 (6 per byte), declaration
lines go through generic JSON at about 40 per byte but are 1.3 % of the bytes (+0.5 per byte overall).
Decoding proof blocks later adds 60 x 67 M = 4.0 G, charged to checking. Acceptance for the loader work
packages: <= 12 instr/byte at M3, <= 8 at M5, measured as `rlvm -X stop-after=load` minus process start.

## 4. Declaration admission

### 4.1 Order, visibility, and why any schedule is sound

- **Unit** = one declaration record. **Rank** = position in admission order; for every file whose
  constants are declared before use (all exporter output, R01 2.7) rank = unit index.
- **Visibility** (official: a constant must be in the environment): while admitting a unit of rank `r`, a
  constant is visible iff its rank is `< r`; inside an inductive block the reference kernel additionally
  exposes the block's own types, then constructors, then recursors, as `add_inductive` does
  (`KernelOps.exposeUnitMembers`).
- **I1** visibility is enforced once per root by `depMax(root) < r` (2.1) instead of at every lookup: a
  sub-term's `depMax` never exceeds its root's, and everything an engine builds while checking the unit
  mentions only constants of the roots and of bodies of visible constants.
- **I2 optimistic environment**: units are admitted against the *statements* of earlier units (rows, and
  for inductive blocks the derived facts), not against their verdicts. Sound because the run is accepted
  only if every unit is: a wrong earlier unit can only make a later check fail, loop or crash, and it
  yields a non-ACCEPT outcome by itself.
- **I3 kept facts are functions of ids.** A fact an engine keeps across units (session caches,
  `SharedFacts`, code objects) may depend only on term/value identity and on immutable published data.
  Then it is valid for every unit that can legally mention its subject. Not keepable: anything that
  depends on a constant being absent, anything computed while a budget was running out or a failure was
  propagating. The three environment-dependent kernel behaviours are made functions of ids: literal
  rules through the literal's `depMax` and the guard state of a cid, quotient reduction through the
  kind of the cid (`QUOT_LIFT`, `QUOT_IND`), unknown constants through I1.
- **I4 totality**: engines must terminate with DECLINE on garbage (bounds-checked ids, step and memory
  budgets, every `Throwable` caught at the unit boundary), because under I2 they may be fed the body of
  an ill-typed earlier definition.
- **I5 sessions move forward** (ISA.md I-SESSION): a session is reset when the next unit's rank is not
  larger than the last one's. With I1 and I3 this is defence in depth, not a necessity; relaxing it for
  the namespace order is an M5 experiment that needs the differential suite green.
- **I6 worker-count independence**: budgets are steps and bytes, never time; a budget decline in a warm
  session is always retried cold with a fixed budget before it counts (6.5).

### 4.2 Names: flat namespace, unbound references, forward references

- One namespace for all kinds including generated names (`I.rec`, `I.rec_N`, the four `Quot` names): the
  `constOf` word of the name, claimed by compare-and-set (2.3). Exported recursor and constructor records
  claim their names at load; a later `def` with the same name is a duplicate (tutorial 135, 137, 138).
- A `CONST`/`PROJ` node whose name has no constant when the node is written stays unbound (`~nameId`,
  flag UNRESOLVED, `depMax = UNRESOLVED`); a `CONST` whose level list has the wrong length is flagged the
  same way. Only the slow path of 4.3 looks at such nodes.
- Slow path outcomes for a root with UNRESOLVED: name dropped as unsafe/partial -> UNKNOWN_CONSTANT
  (tutorial 140, 141); name never declared in the whole file (decided at end of file; the unit is parked)
  -> UNKNOWN_CONSTANT; wrong arity -> LEVEL_ARITY_MISMATCH (`bugs/constlevels`); name declared by a later
  unit -> FORWARD_REFERENCE.
- Forward references: the official replay is by dependency and accepts them when acyclic (R01 2.11); no
  arena test contains one. `Policy.forwardRefs = DECLINE` (v1) exits 2; `REORDER` (later) takes ranks from
  a topological sort with file order as tie-break and rejects a cycle. A reference to the unit itself is
  not a forward reference: names are claimed before the segment is swept, so it binds, gives
  `depMax = own rank`, and is rejected as UNKNOWN_CONSTANT (tutorial 014 `selfProof`).
- Generated constants that the export does not list (official: usable all the same, R01 2.11): the
  environment thread adds them (`CF_GENERATED`, terms in the generated region) and claims their names.
  If the name does not exist yet as a name id, loader and environment thread meet through a small
  concurrent table of late names, each publishing its own entry before looking for the other's, so that a
  later declaration of that name is always seen as a duplicate. v1 declines such files
  (`UNSUPPORTED_INPUT`); canonical files never need it.

### 4.3 Structural checks (`StructuralChecks`, O(1) per root)

```
checkConstant(cid):                                     R03 checklist items 4-8, 11, 12
  lparams distinct                       else DUPLICATE_LEVEL_PARAM        (tutorial 019, 048)
  for root in {type, value if any}:
     looseRange(root) == 0               else LOOSE_BVAR                   (bugs/loose-bvar-value)
     subsetOf(lpSet(root), lparams)      else UNDECLARED_LEVEL_PARAM       (other/inductive-undeclared-universe)
     header(root) has no UNRESOLVED and depMax(root) < rank
                                         else slow path: exact walk -> UNKNOWN_CONSTANT | LEVEL_ARITY_MISMATCH
                                              | FORWARD_REFERENCE | ok (late-bound names)
```

A block-valued theorem has no root node until the block is decoded; the decoder derives the root's
summary in the worker's overlay and the same three tests run there before the engine starts. The name
uniqueness test (items 2, 4) already happened at load. These tests are complete for the official rules
because `tc.check` visits every sub-term (R03 4.1), so a property of the whole expression is a property
of the root summary.

### 4.4 Flow per declaration kind

| Kind | Structural (4.3) | Decided by | Engine work | Thread |
|---|---|---|---|---|
| axiom | lparams, type root | primary engine (`Session.check`) | type is well typed, its type reduces to a sort | worker |
| definition | + value root | primary engine | + value checked, `isDefEq(inferred, declared)` | worker |
| theorem | + value root (block) | primary engine | + `isProp(type)` (throwing), value | worker |
| opaque | as definition | primary engine | as definition | worker |
| quot (4 records) | names are the four reserved ones | `QuotAdmission` | none (structural comparison) | environment |
| inductive block | item consistency, roots of types and constructor types (own unit allowed) | `InductiveAdmission` + `RecordCompare` over `KernelOps` of the reference kernel | section 4.6 | environment |
| unsafe / partial | - | dropped | none | loader |

The primary engine is the machine; before it exists, and under `-X engine=reference`, it is the reference
kernel. `Session.check(cid, budget)` is specified in `rlvm.api.Session`; its preconditions are exactly the
structural checks. After admission, definitions and theorems unfold (`CF_UNFOLDS`; a theorem's hint is
opaque), everything else never does (R03 4.2). Hints are stored verbatim and steer only the lazy-delta
order.

### 4.5 Safety

Records with `safety` in {unsafe, partial} or `isUnsafe = true` are dropped at load: not stored, not
checked, not comparable; only the name is marked (`constOf = -1`). An `inductive` item with an unsafe
type record is dropped as a whole; an unsafe constructor or recursor record inside a safe block is
ignored (the derived safe one exists). This is the official replay (R03 4.4): unsafe and partial constants
are absent, and a safe declaration that mentions one fails with "unknown constant" (tutorial 140, 141 are
rejected, not declined). `mutualDefnDecl` is never needed. The marker also keeps the diagnostic honest
("unknown constant 'unsafeLoop' (dropped: unsafe)").

### 4.6 Inductive blocks: regenerate, compare, commit

```
EnvBuilder, for an inductive unit u (after all earlier inductive and quot units):
  in := BlockInput from the rows and the claims blob                    // checklist 25, 26: consistency, numParams fits
  ops.begin(rank(u), in.levelParams)                                    // reference kernel, admission overlay
  InductiveAdmission.generate(in, gen)                                  // checklist 27-48, R03 6.1-6.12
  present := RecordCompare.compare(in, gen)                             // checklist 49-51: every exported safe ctor/rec record
                                                                        //   has a derived twin and is identical to it
  commit (checklist 52):
     per type: setInductive(numParams, derived numIndices, ctors, all, derived flags, numNested, rec cid)
     per ctor: setConstructor(induct, cidx, numParams, derived numFields)
     per recursor j: if present(j): row keeps the exported type; rules list = exported rhs term ids
                     else: copy derived type and rules into the generated region, add a GENERATED constant
     bind specials and evaluate prelude guards for names of this block
  publishEnv(u + 1); engine.environmentAdvanced(u + 1)
```

- The only inputs are the universe parameters, `numParams`, and the (name, type) pairs of the types and
  of their constructors in the order of the `ctors` lists (R03 decision 1). Exported `numIndices`,
  `isRec`, `isReflexive`, `numNested` are neither used nor compared (official: ignored); the derived
  values are stored.
- Comparison is structural (`TermOps.eqv`: alpha-equivalence, binder info absent, levels by id),
  never definitional (`bugs/rec-rule-proof-irrel*`, `rec-type-proof-irrel`). Because an identical exported
  record is the same term as the derived one, committing "the generated constants, not the exported
  ones" needs no copy: the row points at the exported shared terms.
- Exactness traps T1-T8 of R03 6.13 are requirements on `rlvm-inductive`: annotations stripped from
  binder domains (`TermOps.consumeTypeAnnotations`), simplifying level instantiation for containers
  (`LevelOps.mkMax/mkIMax`), the syntactic output of `whnf` in three places (hence
  `KernelOps.whnfIsSyntactic`, which the reference kernel guarantees), universe name `u`, `u_1`, ...,
  recursors matched by name, auxiliary recursors named `<first type>.rec_j`.
- The optional "type-check then def-eq" fallback of nano-lean for non-identical records is not
  implemented: a mismatch is a rejection, as in the official checker.
- Failure of a unit in the environment pass (reject or decline) stops `envUnits` at that unit: later units
  are never checked, earlier ones still are (they decide the first failure in file order).
- Cost [est]: 7,129 blocks x about 1.5 M instructions (fresh caches, constructor types and recursor types
  checked by the substitution kernel) = 10.7 G on mathlib, 2.7 % of the leader's total, on a thread of
  its own. Measured at M3 on Init (605 blocks). Two reductions are prepared and off by default: yes/no
  judgments through the machine's `KernelOps`, and `Policy.trustMatchingRecursors` (skip the defensive
  re-check of a derived recursor that equals the exported one).

### 4.7 Quot

On the first `quot` record: `Eq` must be an admitted inductive type with one universe parameter, one
constructor, type `Pi(Sort u, Pi(#0, Pi(#1, Sort 0)))` and constructor type
`Pi(Sort u, Pi(#0, Eq.{u} #1 #0 #0))`; the four names must be claimed by quot records only. Every quot
record must have kind, universe parameters (`[u]`; `[u, v]` for lift) and type identical to the canonical
ones of R03 section 5, built in the overlay and compared with `eqv` (`bugs/quot-bad-type`). A quot record
under any other name is rejected (stricter than official, harmless). Quotient reduction is a property of
the kinds `QUOT_LIFT` and `QUOT_IND`, so it exists exactly for units after the quot unit.

### 4.8 Literal prerequisites and prelude guards

The official kernel validates nothing about `Nat`, `String` and the accelerated functions (R03 section 8);
the arena promises official preludes (R01 4.3). RLVM implements level L1: shape guards, evaluated by the
environment thread when a declaration with a special name is admitted (`PreludeGuards`):

| Special | Guard (structural, no reduction) | Enables |
|---|---|---|
| `Nat`, `Nat.zero`, `Nat.succ` | `inductive Nat : Type` with exactly these constructors, `succ : Nat -> Nat` | Nat literal typing, literal/constructor views |
| `Nat.add` .. `Nat.shiftRight` (13 functions) | safe definition, no universe parameters, type `Nat -> Nat -> Nat` | binary acceleration of that function |
| `Nat.beq`, `Nat.ble`; `Bool`, `Bool.false`, `Bool.true` | type `Nat -> Nat -> Bool`; `inductive Bool : Type` with these two constructors | boolean acceleration |
| `String`, `String.ofList`, `Char`, `Char.ofNat`, `List`, `List.nil`, `List.cons` | `String.ofList : List Char -> String`, `Char.ofNat : Nat -> Char`, standard `List` constructors | string literal typing and expansion |
| `eagerReduce`, `Eq`, `Eq.refl`, `Quot*` | bound; `Eq` checked in 4.7 | - |

A special is ABSENT (never declared: the extension does not fire, as in the official kernel), VALID, or
INVALID. An engine that needs an extension whose special is INVALID raises
`ResourceException(UNSUPPORTED_PRELUDE)`: the unit is declined, neither accepted nor rejected on the
strength of a non-standard prelude. A file that declares an odd `Nat.add` and never computes with it gets
its normal verdict. Bodies of the accelerated functions are not validated (official behaviour; level L2 of
R03 is future work). For exports of older Lean versions the string hook `String.mk` is bound as a
fallback when `String.ofList` is absent (R07 2.6; open point O4).

## 5. Reference kernel (`rlvm-ref`)

- **Scope**: the complete official type checker of v4.36.0 as specified in R02: `infer` in check and
  infer-only mode, `whnf_core` with the cheap flags, `whnf` with delta, the 15-function Nat extension,
  string literal expansion, quotients, iota with K and structure eta on majors, projections;
  `is_def_eq` with the exact step order of R02 8.1 (quick test, proof irrelevance, lazy delta with
  hints, congruence, eta, unit-like), level comparison through `LevelOps`. Locally nameless: binders are
  opened with `FVAR` overlay nodes; substitution is `TermOps`.
- **Representation**: term ids; results built in the worker's overlay, hash-consed there. Equality fast
  path is id equality; `eqv` where the official code compares structurally.
- **Caches**: the seven of R02 section 5 (infer x2, whnf_core, whnf, def-eq successes, same-head
  failures, unfold), as open-addressing `int` tables keyed by term ids, cleared per declaration
  (`KernelOps.begin`). Nothing survives a declaration, so its verdict is trivially deterministic. No
  union-find, no negative cache, no shortcut the official kernel lacks.
- **API**: `RefKernel implements KernelOps` (+ `setBudget`, `checkConstant(cid)`); `RefEngine implements
  Engine` with `RefSession` (one `RefKernel`, `check` = structural preconditions assumed, then the
  official `add_*` body).
- **Uses**: (1) all judgments of the environment pass; (2) confirmation of every rejection of the primary
  engine and fallback for its declines (8.2); (3) oracle of `DiffEngine` and of the `KernelOps`-level
  differential tests; (4) primary engine until the machine exists (M1-M3) and under `-X engine=reference`.
- **Recursion**: recursive like the original. It runs only on threads with a 1 GiB stack (environment
  thread, heavy-lane threads), counts depth, and raises `ResourceException(STACK_DEPTH)` before the stack
  ends; `StackOverflowError` is caught as a backstop. Term traversals in `TermOps` are iterative.
- **Cost off the hot path**: in an accepting run it executes only the environment pass (about 10 G on
  mathlib, own thread). Re-checks happen only for units the machine did not accept. In a differential
  run it doubles the work by design.
- **Performance floor** (it is the fallback): a plain Java port with object terms and `HashMap` caches
  (tenet-jvm) checks Init in 37 virtual seconds and mathlib in 1,633 (R01 1.5); with ids and primitive
  tables the target is <= 300 G on Init at M3 and all 8 `perf/*-bad` tests within their arena timeouts
  (official needs 4.7-14.2 virtual seconds on them, timeouts are 110-130 s).

## 6. Scheduler and parallelism

### 6.1 Threads

| Thread | Count | Stack | Work |
|---|--:|--:|---|
| launcher main | 1 | default | waits, owns the exit status (`rlvm-cli`) |
| loader (`rlvm-checker`, created by the launcher) | 1 | 512 MiB (launcher default) | read, scan, sink; joins the others at end of file |
| scan helpers | K = 0 | default | tokenise file ranges (3.5) |
| environment | 1 | 1 GiB | inductive and quot units in admission order, reference kernel (4.6) |
| workers | W = 6 | 64 MiB | check units with the primary engine; no host recursion in the machine (ISA.md 0.1) |
| heavy lane | 0-2, on first use | 1 GiB | cold retries, reference-kernel re-checks and fallbacks (6.5, 8.2) |
| Truffle compiler | 1 | - | background compilation of promoted code objects (ISA.md 0.14) |
| collector | 0 | - | Serial GC runs on the allocating thread |

Stack sizes are reservations; pages are committed when touched. With `-j 1` the same code runs with one
worker; the environment pass can then be driven lazily by that worker (`EnvBuilder.advanceTo`).

### 6.2 Order of units

Any order of units gives the same verdict (4.1: a unit sees exactly the constants of smaller rank, and
kept facts are functions of ids). The order only decides cache warmth.

- `FILE` (default): the exporter's order is a dependency post-order from hash-ordered roots (R01 2.7): a
  declaration follows the dependencies it introduced, but consecutive roots are unrelated.
- `NAMESPACE_WINDOW`: inside a sliding window of 16,384 ready units, group by the first two name
  components (after stripping `_private.<module>.0.`), groups in order of first appearance, file order
  inside a group. Evidence for grouping: pestka -9 % instructions on mathlib slices, gruszka -5 % for
  contiguous slices against round robin (R05 0.6, 2.10); nano-lean reorders towards dependencies (R04
  12.1). A window instead of the whole file keeps the pipeline (3.5); the cost is a session reset at each
  group boundary where the rank steps back (I5).
- Decision rule (M5, WP-P1): switch the default to `NAMESPACE_WINDOW` if mathlib instructions drop by 2 %
  or more with the verdict-invariance suite green.

### 6.3 Work distribution

```
ready     = units below min(envUnits, firstFailure + 1) not yet handed out, arranged window by window
claim(w)  = the next n = min(chunkUnits = 32, max(1, backlog / (2 W))) units of that order; if none: park
            (one short lock per claim; about 22,600 claims on mathlib; nothing else in the loop locks)
worker    = for u in claim: Terms.refresh(); admit(u) with Budget.warm(); record; maybe reset (6.4)
giveBack  = a unit took more than 20 ms: the unstarted rest of the claim goes to a shared stack
            that claim() serves first
skip      = inductive and quot units (decided by the environment thread), SKIPPED units
```

Workers therefore see increasing ranks inside a claim and mostly from claim to claim, and neighbouring
declarations stay on one worker. Idle workers park and are unparked at publications; no thread spins.

### 6.4 Sessions

A session is the engine's `Session` plus the worker's `WorkerContext` (term overlay, list, level and
literal overlays). It lives across units and is reset (`Session.reset()` + `WorkerContext.reset()`; cost
proportional to what was used) when:

1. its footprint exceeds `sessionBytes` = 32 MiB (overlay terms + engine arenas);
2. a unit ended with anything but ACCEPT (nothing from a failed or abandoned unit is kept);
3. the next unit's rank is not larger than the last one's (I5);
4. the next unit lies beyond the worker's level snapshot (3.5);
5. the worker moves to the heavy lane or to a re-check (always a fresh session).

32 MiB is the middle of the leaders' range (gruszka 8 MiB of table entries, sokonanoda 9 MiB, nano-lean
64 MiB arena; R04 12.3, R05 2.9, R06 0.5) and is swept over 8 / 16 / 32 / 64 at M5. Mathlib decodes
67 M x 32 B = 2.1 GB of block nodes in total, so with engine data a worker goes through a few hundred
sessions per run [est]; a reset that costs a millisecond is irrelevant.

### 6.5 Budgets, the heavy lane, determinism

- Warm attempt: `Budget.warm()` = 5 x 10^7 steps and 1 GiB. On exhaustion the session is reset and the
  unit is deferred (`Scheduler.defer`).
- Heavy lane: fresh session, deep-stack thread, `Budget.cold(memory)`: unlimited steps, memory up to the
  run's limit. A unit ends there with ACCEPT, REJECT (then 8.2), or DECLINE. If the primary engine
  declines, the reference kernel gets the unit with the same cold budget before the decline counts.
- No budget is expressed in time. A timeout would be scored exactly like the decline it tries to avoid
  (R01 1.3), and mathlib must never be cut short.
- Determinism: ACCEPT and REJECT are semantic facts and do not depend on cache warmth (I3). A budget
  DECLINE in a warm session is never final. The cold attempt is a function of the store, the unit and
  the budget constants. Remaining schedule dependence: a unit that fits the memory limit only with warm
  caches may be accepted in one schedule and declined in another; it can change a decline into an accept,
  never an accept into a reject.
- Cancellation: `RunSignals.firstFailure()` is polled by engines every few thousand steps (ISA.md 1.4:
  4096 ticks); a unit above the first failure stops with a `ResourceException` and is not recorded.

### 6.6 Failure handling

| Event | Response |
|---|---|
| primary engine REJECT | the worker resets its session and continues; the unit goes to the re-check protocol (8.2) on a heavy-lane thread |
| confirmed REJECT or final DECLINE of unit f | `firstFailure = min(firstFailure, f)`; units above f are no longer handed out and running ones abandon; units below f run to completion, so the reported failure is the first in file order |
| environment pass fails at unit f | same, and `envUnits` stays at f for good |
| `MalformedExportException` | input failure: REJECT at once, everything is cancelled (official: the reader throws before any checking) |
| `UnsupportedExportException` | loading stops; published units are still checked; verdict REJECT if one of them is rejected and confirmed, else DECLINE |
| `RuntimeException` out of an engine at a unit boundary | session discarded; the unit is retried once by the reference kernel in the heavy lane; if that also throws: DECLINE(INTERNAL_ERROR) |
| `Error` on any thread (`OutOfMemoryError`, `StackOverflowError`, assertion) | not handled: the launcher's uncaught-exception handler and `ExitOnOutOfMemoryError` end the process with status 3 (`rlvm-cli` contract: never catch `Error` to carry on). Depth counters and the memory account exist so that this does not happen |

### 6.7 Memory reclamation

- Loader transients (`loc`, promotion table, segment buffer, claims blobs, reader buffers) are dropped at
  end of file; they are plain arrays without references into them, so dropping is free.
- Session memory is reused, not freed: resets move pointers. An overlay or engine arena that one huge
  declaration made grow is replaced by a base-size array at the next reset.
- Shared terms and proof blocks live to the end (theorems can be unfolded, R03 4.2).
- Every large array is registered with the run's memory account (`rlvm-driver`); above
  `memoryLimitBytes` (12 GiB) `RunSignals.memoryExhausted()` turns true and units decline instead of
  letting the runner's OOM killer end the process (exit 137, also scored as a decline, but uncontrolled).
- At the end the launcher calls `Runtime.halt`: no teardown is paid for.

### 6.8 Default thread count on the 8-vCPU runner

`workers = max(1, min(processors, 8) - 2)` = 6, leaving two CPUs for the loader, the environment thread
and the compiler thread; the loader's CPU is free again after the first half of the run. Expected cost
against one worker: +0.8 % to +1.6 % instructions [src gruszka, a design without collector work; R11 C.5
measures +7 % to +10 % when the working set is made of objects, which this design excludes]. Sources of
the overhead here: facts found once per worker instead of once, and code objects elaborated concurrently
by two workers. Gate before submission (WP-P1), on mathlib in the arena-shaped container:

| `-j` | instructions | wall | decision rule |
|---|---|---|---|
| 1, 2, 4, 6, 8 | measure each 3 times | measure | default = the largest N <= 6 whose instructions exceed `-j 1` by <= 2 %; the draft `rlvm.yaml` says `--threads 4` until then |

### 6.9 Measuring wall clock, CPU time and instructions

- Instructions: only from outside, exactly as the arena does: `scripts/dev.sh measure EXPORT`
  (`bench/rlvm/measure.sh`: `perf stat -e instructions:u` in the 8-CPU / 16 GB container, for 1, 4 and 8
  threads). Phase attribution by differencing: `-X stop-after=load` and `-X stop-after=env` end the run
  after the phase with status 2.
- Wall clock and CPU: `RunStats` records `System.nanoTime()` at phase boundaries and per-thread CPU time
  at thread end (the launcher's `ProcStats`); `--stats` prints them; `-X stats-file=F` writes JSON with
  loader counters, steps per unit (top 50), units and resets per worker, peak accounted bytes, and the
  engines' heat tables (`Engine.dumpStats`).
- Steps (the engines' deterministic work unit) are the bridge between the two: instructions per step
  per phase is the number tracked from commit to commit.
- All of it is off by default and then costs one predictable branch per unit.

### 7.2 Collector configuration, and why the working set is invisible to it

What is in the Java heap as objects: a few hundred long-lived singletons and array headers; the Truffle
tier's node trees and compiled code for promoted code objects (thousands of objects, never collected);
short-lived `long[]` temporaries of big-number arithmetic; diagnostics strings when enabled. Everything
that scales with the input is a primitive array whose content no collector reads: term regions, proof
blocks, names, tables, overlays, engine arenas, worklists. Cost model that this avoids (R11 0.3): about
10 instructions per surviving byte at promotion and 380 per object per full collection, i.e. 34 G to
promote 105 M node objects once.

Consequences: young collections are rare (only big-number garbage fills the nursery) and find almost
nothing alive besides shallow thread stacks (the machine keeps no deep Java stack: 680 instructions per
live frame per collection, R11 B.11); full collections do not occur because the old generation only
grows by long-lived arrays and is sized above the memory account's limit; the collector choice then
changes nothing measurable, and Serial is taken because it has no helper threads to bill (R11 0.5).
The owner's observation that single-thread collector totals mislead (OWNER-NOTES 2) is answered by
removing the collector from the workers' path rather than by tuning it: R11 C.5 measured +9.8 %
instructions and 2.4x process CPU for four allocating mutators under Serial with a 1 GB nursery (+7.2 %
with 4 GB).

| Launcher | Flags (changes to `scripts/build.sh` in bold) |
|---|---|
| native image | `--gc=serial -R:+ExitOnOutOfMemoryError` **`-R:MaxHeapSize=13g -R:MaxNewSize=1g`** |
| JVM | `-XX:+UseSerialGC -XX:+ExitOnOutOfMemoryError -XX:-UseJVMCICompiler -XX:CICompilerCount=2` **`-Xms13g -Xmx13g -Xmn1g`** (was 8g / 8g / 3g, sized for an object working set); no `AlwaysPreTouch`, no `System.gc()` |

13 GB of heap on the 16 GB runner leaves 3 GB for stacks, code and the page cache's pressure; the memory
account declines at 12 GiB, before the heap limit. Large arrays are allocated before anything else where
possible so that they sit at the bottom of the old generation (R11 B.3).

### 7.3 Thread stacks

Worker 64 MiB (the machine is a worklist stepper; only the loader's reader and engine fast paths recurse,
boundedly); environment and heavy-lane threads 1 GiB (the reference kernel recurses like the original;
`perf/app-lam` is 19,999 binders deep); all created with `new Thread(group, body, name, stackBytes)`,
which HotSpot and the image both honour. The reference kernel counts depth and declines before the
stack ends.

## 8. Verdict and error policy

### 8.1 Statuses and the fail-closed chain

| Status | Meaning | Arena |
|--:|---|---|
| 0 | every unit ACCEPTED (or SKIPPED as unsafe/partial), end of file reached, counts consistent | accepted |
| 1 | malformed input, or a rejection confirmed by the reference kernel | rejected |
| 2 | no confirmed rejection, but something was declined | declined |
| 3 | internal error: an `Error`, a dead thread, a launcher failure (`rlvm-cli`) | error (scored like a decline) |
| 64 | usage error | error |

Three independent defaults must all be overturned for a 0: the launcher's status starts as 3 and takes
a verdict only from a normally returned `check`; `VerdictBoard.exitCode()` is DECLINE until
`complete(units)` was called by the loader at end of file; and `complete` yields ACCEPT only if
`accepted + skipped == units == declaration records counted by the reader` and no unit has another
status. Every unit status is written once, by compare-and-set from RUNNING.

Scoring logic behind the choices (R01 1.3): the sort key is (bad accepted, good rejected, mathlib
instructions, declined). A wrong answer in either direction outweighs any speed; a decline, a crash and
a timeout all cost one unit of the last tie-breaker. Hence: never guess; when unsure decline; but do not
decline lightly on mathlib, because a decline there removes the checker from the speed ranking.

### 8.2 Re-check protocol

```
primary engine says REJECT for unit u (in a warm session):
  1. cold strict run of the primary engine (fresh session, EngineConfig.strict, Budget.cold)
        ACCEPT  -> u accepted; logged as WARM-ANOMALY (a cache or shortcut produced a wrong rejection; test builds fail)
        other   -> 2
  2. reference kernel on u (fresh session, deep stack, Budget.cold)
        REJECT  -> u REJECTED, confirmed; the reported reason is the reference kernel's
        ACCEPT  -> u accepted; logged as MACHINE-INCOMPLETE (the machine failed to prove a true equation)
        DECLINE -> Policy.unconfirmedReject: DECLINE(UNCONFIRMED_REJECT) (default) or REJECT
primary engine says DECLINE in the heavy lane:  reference kernel as in 2; its ACCEPT or REJECT is final
rejections that need no confirmation:  structural checks (4.3), the environment pass (already the reference
  kernel), the loader (malformed input)
```

- An ACCEPT of the primary engine is never re-checked: that is the hot path, and its soundness is the
  machine's own obligation (ISA.md; differential testing, 9.2).
- Accepting on the reference kernel's word after the machine rejected is sound: the reference kernel is
  a complete checker in its own right, and "shortcuts fail open into the complete official procedure" is
  exactly this step at the granularity of a declaration.
- `unconfirmedReject = DECLINE`: when the machine rejects twice and the reference kernel cannot finish,
  a decline costs one tie-breaker point, a wrong rejection of a good test costs the second sort key. The
  policy flips to REJECT only if the differential campaign of M4 shows no MACHINE-INCOMPLETE event and a
  `perf/*-bad` test needs it.
- Cost: nothing on accepting runs. On rejecting runs the reference kernel must finish within the test's
  timeout; that is an acceptance criterion of WP-R3 for the eight `perf/*-bad` tests.

### 8.3 Resource exhaustion and internal errors

| Situation | Outcome | Why |
|---|---|---|
| step budget of the warm attempt | retry cold (6.5) | not a verdict |
| memory account over the limit | units DECLINE(BUDGET_MEMORY); status 2 | a decline is controlled; exit 137 is not |
| depth limit of the reference kernel | DECLINE(STACK_DEPTH) for that judgment's unit | never a rejection (tenet-jvm and rpylean map it to "rejected"; R07) |
| INVALID prelude special used | DECLINE(UNSUPPORTED_PRELUDE) | 4.8 |
| engines disagree in differential mode | DECLINE(ENGINE_DISAGREEMENT) and a test failure | never ship a guess |
| exception inside an engine | reference-kernel retry, else DECLINE(INTERNAL_ERROR) | 6.6 |
| `Error`, dead thread | status 3 | `rlvm-cli` contract |
| the arena's timeout | (process killed) | budgets are not time-based; the machine's speed is the remedy |

### 8.4 Diagnostics that cost nothing when off

- Default output: nothing on accept; on any other verdict one line on stderr (unit index, constant name,
  reason, the reference kernel's message). The arena keeps 100 lines / 8 KiB (R01 1.1).
- `Session.lastMessage()` and name rendering run only after a failure. No logging framework, no string
  formatting, no boxed values on any path that runs per node or per step.
- Tracing, memo checking and id poisoning are compiled in only in the debug distribution: they hang off
  `static final boolean` flags that are constants at image build time (system properties read in a class
  initialised at build time), so the release image contains no test for them.
- Statistics (`--stats`, `-X stats-file`) are collected per unit and per phase, never per step; the
  engines' heat counters follow the same rule (`EngineConfig.stats`).

### 9.2 Differential tests

- **Engine against engine**: `-X engine=diff` (`rlvm.testkit.DiffEngine`) runs machine and reference
  kernel on every unit of the arena tests, Init, Std and mathlib slices (`work/exports/slices/`). Any
  ACCEPT/REJECT difference fails. Below that, a sampler compares `KernelOps` answers (`whnf` up to
  def-eq by the reference kernel, `isDefEq` exactly, `infer` up to def-eq) on sub-terms of real proofs.
- **Against the official checker**: `rlvm.testkit.Leanchecker` wraps `leanchecker --from-export` of the
  pinned 4.36.0 toolchain; verdicts cached by file hash. Inputs: the 230 tests, and mutants from
  `ExportMutator` (forged counts, flags and rules, swapped children and levels must be judged like the
  official checker judges them; changed hints, renumbered ids and reformatted JSON must not change the
  verdict). A mutant on which RLVM accepts and the official checker rejects blocks everything.
- **Invariance**: the verdict and the first failing unit must be identical under `-j 1 / 2 / 6`, batch /
  pipelined loading, file / namespace order, session cap 1 MiB / 32 MiB, proof blocks on / off, Truffle
  tier on / off. This is the test of I1-I6.
- **Self-checking builds** (debug distribution): every memo hit recomputed cold (nano-lean's
  `memocheck`, R04 section 2); freed overlay ranges poisoned so that a stale id faults (gruszka);
  `fvMask` re-derived by naive traversal on use (ISA.md 2.4).

### 9.3 The arena suite

`scripts/dev.sh suite` (`bench/rlvm/suite.sh` -> `bench/run-suite.py`, the arena's scoring): 138 accept,
92 reject. `--docker` adds instruction counts under the arena's limits and per-test timeouts. Required
from M2 on: 0 wrong answers; declines listed by name and justified. `bench/compare-published.py`
compares with the published leaders. The 30 "either" tests are run for information when their exports
are built (`work/exports/all/either/`).

### 9.4 Performance tracking

- Corpus ladder: init-prelude (3.8 MB), Init (348 MB), Std (584 MB), ten mathlib module cones
  (`work/exports/slices/`), cslib (2.5 GB), mathlib (6.3 GB). Per commit on the main line: init-prelude,
  Init and two slices; nightly: the rest.
- Recorded per run (`scripts/dev.sh track`, to be added; appends to `work/perf-history/<corpus>.jsonl`):
  commit, launcher, threads, instructions, kernel instructions, wall, CPU, RSS, steps, phase split.
  Instructions from `bench/measure.sh` only; never CPU time as a proxy (R11: the two disagree by up to
  2x in both directions).
- Regression rule: +1 % instructions on Init or a slice needs a justification in the commit. Native
  runs repeat to 0.1 % single-threaded; multi-threaded and JVM runs are measured three times (the JVM
  varies by about 2 %, `bench/README.md`).
- Targets are stated against leaders measured on this host with the same script (`bench/baselines/`),
  not against published x86 numbers (the official C++ kernel counts 5 % fewer instructions here).

## 11. Boundary to ISA.md

Provided to the machine:

- the store API of section 1.3 with the layouts of section 2 (normative: `rlvm.store.Node`), including
  per-node `fvMask` that never under-approximates, `looseRange`, `HAS_LPARAM`, `depMax`, `lpSet`, and three
  header bits plus the `c` word of LAM/PI nodes for the elaborator's own static facts;
- constant rows and derived inductive facts readable for every unit below `envUnits`; `Specials` with
  guard states (`natOk`, `boolOk`, `stringOk` of ISA.md 2.9 are `state(NAT..)`, `state(BOOL..)`,
  `state(STRING..)`); `SharedFacts` as the shared check-mode table (`PCHK`);
- a `WorkerContext` per session: term overlay (decodes proof blocks, holds terms the machine builds),
  list / level / literal overlays, `RunSignals` (first failure, memory);
- lifecycle: sessions only move forward in rank; `reset()` is called by the driver on the conditions of
  6.4 and always before a cold or strict run; `Terms.refresh()` at every unit start;
- preconditions of `Session.check` (4.3) and the guarantee that a REJECT is confirmed elsewhere.

Required from the machine:

- `Engine` / `Session` as specified in `rlvm.api`, registered as an `EngineProvider`;
- outcomes that are functions of ids (I3), nothing kept from abandoned or failed work, DECLINE on every
  limit, termination on ill-typed input (I4);
- no writes to shared store data other than `SharedFacts` and its own engine-wide tables, which must be
  safe under concurrent sessions and must not make a verdict depend on which session filled them;
- `EngineConfig.strict` (no shortcut, no cache across units) for the re-check, `footprintBytes()` and
  `steps()` that are cheap and honest, `dumpStats` for heat;
- `KernelOps` from the machine is optional; admission uses the reference kernel in v1.

## 12. Risks and open questions

Risks:

1. **AOT code quality** (7.1): if the gate is not run, up to 1.4x of the machine's instructions is left on
   the table; if it picks the JVM, start-up and warm-up variance (about 2 %) enters every measurement.
2. **Exact syntactic regeneration of recursors** (R03 6.13) is the largest correctness item outside the
   machine; a mismatch rejects a good file. Mitigation: Init's 605 and mathlib's 7,129 blocks as
   regression corpus from M2 on.
3. **Reference kernel speed** decides whether rejections are confirmed within timeouts and whether the
   fallback rescues mathlib; its floor is set by acceptance criteria (R3), not by hope.
4. **Pipelined loading** depends on a level-store snapshot; without it the wall-clock model of 3.5 loses
   15 s on mathlib (batch mode), nothing else.
5. **Shared-region estimate** (36 % of records) comes from Susz's numbers for an earlier mathlib; a
   growth copy costs a transient 1.8 GB. Mitigation: measured ratio at M3, head-room adjusted.
6. **Optimistic environment** makes every engine face ill-typed bodies; a hang there is contained by
   budgets and cancellation only if polls are frequent (ISA.md 1.4).
7. **Parallel overhead** above 2 % would cost rank; the gate then lowers the default, at the price of
   wall clock.
8. **`Error` handling**: a `StackOverflowError` in the reference kernel ends the run with status 3 under
   the launcher's contract; depth accounting must be conservative.

Open questions:

- O1. Does the level store get `snapshot()` (1.4)? Otherwise pipelining needs its own level table in
  `rlvm-load`.
- O2. May the arena build download Oracle GraalVM (GFTC) if PGO wins the platform gate?
- O3. AoS (this document) or columns (R11 B.3, ISA.md 1.1 wording) for term nodes: decided by WP-A1's
  measurement in the image; the accessor API is the same.
- O4. String-literal hook for exports of Lean < 4.36 (`String.mk` against `String.ofList`): do
  navier-stokes-euler and reachability (4.34.x) contain string literals that must expand? (R01 6.5)
- O5. Forward references and generated-but-unlisted constants: decline in v1; implement only if an arena
  test appears.
- O6. Session cap, order policy, worker count, scan helpers: defaults above are starting values; the
  gates of 6.2, 6.4, 6.8 decide.
- O7. Is the arena's instruction count user-only (R01 1.2)? If kernel instructions count, page faults of
  the 4 GB working set and `read` copies become costs; `MAP_POPULATE`-style pre-touching would then be
  wrong and array reuse more valuable.
