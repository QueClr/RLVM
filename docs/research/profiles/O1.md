**What the gate reports for a switch that changes records and ticks by design.**

- Parts 1 and 5 (differential, pipeline) compare verdicts: the switch shows only in the tick column (Init 39.45 M ->
  40.77 M, Std 64.47 M -> 66.77 M).
- Part 2 (tier equivalence) compares the outcome and reason of every declaration, and K1 values, with the generic
  tier: a switch that changes memo contents and ticks is neither flagged nor bounded by it. There is no part that
  compares the switch set with the set without the switch; the +0.4 to +5.6 % ticks have to be read off the counts.
- Part 3 (convention equivalence) runs all three lanes WITH the switch and compares ticks, call events, the trace and
  every record word: it passes only if the switch itself is independent of the host depth bound. That is the part
  that failed on X1's filter (section 1, item 4) and it is the right test for this class of switch: `gated`'s finding
  M8-F1 was the same kind.
- Part 4 (audits): the audit lanes run under `scopeaudit,maskaudit` and `memocheck,shortcheck`, which are exactly the
