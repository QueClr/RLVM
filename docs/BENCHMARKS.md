## What the numbers are

- **Order (owner note 12): warm wall clock with 8 workers and pipelined loading, warm wall clock with 1 worker, cold
  wall clock of a fresh process, CPU time, peak RSS, instructions.** The first two are in the section "Warm wall
  clock" at the end (`bench/warm.sh`: the same process checks the same export again; full table in
  `work/status/warm.md`). Every OTHER table here is one fresh process per run on a batch load (what the arena
  runs), i.e. cold wall clock and its CPU time, which charge the warm-up that the owner's target does not.
  CPU time is `perf stat` task-clock summed over all threads and child processes; instructions are user-space
  instructions; peak RSS is GNU time's maximum resident set size of the process tree's largest process.
- **Where**: this host (aarch64; Cortex-X925 performance cores), one fresh container per run, shaped like the arena
  runner: 8 CPUs, 16 GB, no network (`bench/arena-docker.sh --arena-limits --no-network bench/measure.sh`). The arena
  itself runs on x86-64; absolute numbers differ, ratios between checkers carry over only roughly.
- **RLVM columns**: one per engine (`-X engine=NAME`), native image, `--threads 8`, batch load, the arena's
  run line otherwise (`scripts/arena/rlvm.yaml`, whose own thread count is 4). **RLVM machine** is the engine that
  ships (`rlvm-machine`: the worklist machine; the DEFAULT engine since 2026-11-24T19:41Z, so `-X engine=machine` is what a
  plain run does; a unit it declines is checked by the reference engine, whose time is part of the figure);
  **RLVM reference** (`-X engine=reference`) is the fallback and re-check engine, the default until then.
  native = the CE native image `bin/rlvm` (`-O3`); JVM = `bin/rlvm-jvm` (GraalVM CE 25, SerialGC,
  13 GB heap, so its RSS is mostly heap reservation that was touched). Which launcher ships and why: `docs/PLATFORM.md`.
