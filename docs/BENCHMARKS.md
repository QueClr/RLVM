## What the numbers are

- **Order of importance: CPU time, wall clock, peak RSS, instructions** (owner note 10). CPU time is `perf stat`
  task-clock summed over all threads and child processes; instructions are user-space instructions; peak RSS is
  GNU time's maximum resident set size of the process tree's largest process.
- **Where**: this host (aarch64; Cortex-X925 performance cores), one fresh container per run, shaped like the arena
  runner: 8 CPUs, 16 GB, no network (`bench/arena-docker.sh --arena-limits --no-network bench/measure.sh`). The arena
  itself runs on x86-64; absolute numbers differ, ratios between checkers carry over only roughly.
- **RLVM**: engine `reference`, `--threads 8`, batch load, the arena's run line otherwise
  (`scripts/arena/rlvm.yaml`, whose own thread count is still 4). JVM = `bin/rlvm-jvm` (GraalVM CE 25, SerialGC, 13 GB
  heap, so its RSS is mostly heap reservation that was touched); native = the CE native image `bin/rlvm`.
- **Baselines**: gruszka, nano-lean and the official checker (`leanchecker`, arena version v4.35.0) with the run lines
  of the arena's checker definitions (gruszka and nano-lean use 4 threads, the official checker one), measured the
  same way on the same host (`docs/research/12-baselines.md`, `bench/baselines.json`).
- **Figure of a cell**: minimum CPU time and wall clock over the runs of the entry (other containers share the eight
  cores and can only add time), maximum RSS, median instructions. The run count, the date and the host's load
  average are in the provenance table at the end. `-` = not measured on this host.
- **Regression rule** (`bench/track/README.md`): an RLVM entry more than 3 % above the reference of its
  configuration in CPU time is a regression; the cells below are those references.
- **How quiet the host was**: 1-minute load average at the start of the 75 RLVM runs: minimum 3, median 115, maximum 186 (20 CPUs; the container has 8 of them to itself only
  as far as other jobs are pinned elsewhere). Contention inflates CPU time and wall clock, never instruction counts.
  Between the runs of one three-run entry, CPU time differs by 1.0 % to 28.8 % (median 7.2 %): read CPU differences below that as noise.
